## Canon Change
A canon change requires:
1. explicit approval
2. documented reason
3. affected file(s)
4. version increment where appropriate
5. updated master reference if visual identity changes
6. review of downstream automation rules

## Generated Asset Rule
Generated images, videos, voices, prompts, and temporary production outputs are not canon by default.

## Version Format
Use semantic-style versions:
- MAJOR: breaking canon/system change
- MINOR: approved new canon capability or non-breaking expansion
- PATCH: wording, correction, or documentation fix

## Audit Principle
Every important production decision should be traceable to:
- a Bible rule
- an approved reference
- an episode decision
- or an explicit change record

## Frozen Canon
Once a character or environment is approved as master canon, automation must treat it as locked until an explicit update is approved.
